`Room → วางบริบท → เห็น evidence → ได้ next action → ย่อยงานให้เล็กลง → กลับมาทำต่อ`

   ```bash
   curl -s http://127.0.0.1:11437/api/tags | head -5
   ```
2. ตรวจว่า model `gemma2:2b` พร้อม
   ```bash
   ollama list   # ต้องเห็น gemma2:2b
   ```

   ```bash
   npm run dev:local-ai
   ```
   ❌ **ห้ามใช้** `npm run dev:raw` — จะชี้ไป port 11434 ซึ่งไม่ตอบ

## วิธีเดโม — 3 ช่วงหลัก

### ช่วง 1: Context → Next Action (ประมาณ 3 นาที)

1. สร้างห้องใหม่ หรือเลือกห้องเดิม
2. วางข้อความงานค้าง
3. แนบไฟล์ 1 ไฟล์ (ถ้ามี)
4. กด **`ไปต่อ`** — ปุ่มจะเปลี่ยนเป็น "กำลังสรุป..." ระหว่างรอ
5. เห็น **ONE_ACTION** พร้อม evidence chip
6. กด evidence chip → เปิด **`ดูที่มาของก้าวนี้`**
7. ชี้ให้เห็นว่า source text มาจากข้อความ/ไฟล์ที่วาง

### ช่วง 2: Scaffold + Make-Smaller (ประมาณ 2 นาที)

8. กด **`ใช้ก้าวนี้`** → เข้า Scaffold card
9. ชี้ให้เห็น **context header** (`ขั้นตอน 1 / X`) และ step detail
10. กด **`แบ่งก้าวนี้ให้เล็กลง`** → AI สร้างขั้นตอนย่อยที่เล็กลง
    - ⏱️ รอ ~3-8 วินาที (local CPU model)
    - ✅ เห็น step ใหม่ที่เล็กลงจริง โดย context งานไม่ reset

### ช่วง 3: Recovery + Reentry (ประมาณ 2 นาที)

11. กด **`ช่วยดูให้หน่อยว่าติดตรงไหน`** → เปิดจอ Rescue/วินิจฉัย
12. กด **`กลับไปแก้บริบทให้ตรงเคส`** → กลับหน้า Input
    - ✅ ข้อความเดิม + ไฟล์ที่แนบยังอยู่ครบ
    - ✅ เห็น banner "บริบทเดิมยังอยู่ครบ แก้ได้เลย"
13. กด **`พักงานนี้ไว้ก่อน`** → กลับหน้าหลัก
14. เลือกห้องเดิมจาก sidebar → **Reentry**
    - ✅ context กลับมาครบ
    - ✅ sidebar แสดง `กลับมาทำต่อ`
    - ✅ เห็น reentry chips: `ใช้บริบทจากข้อความเดิม`, `มี reentry brief ล่าสุด`

## สิ่งที่ต้องสังเกต

- คนดูลังเลตรงไหนก่อน
- คนดูถามว่าต้องกดอะไรต่อไหม
- evidence ทำให้ก้าวถัดไปน่าเชื่อขึ้นไหม
- make-smaller สร้าง step ที่เล็กลงจริงไหม
- กลับไปแก้บริบทแล้วรู้สึกว่าของเดิมยังอยู่ไหม
- reentry อ่านเป็นการทำงานต่อ หรือดูเหมือนเริ่มใหม่

## สิ่งที่ต้องจด

- จุดลังเลแรก
- คลิกแรกที่คนดูเลือก

- อะไรที่ดูดี
