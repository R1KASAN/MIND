# Demo Cycle Life

สคริปต์พรีเซนต์แบบ 1 หน้า สำหรับโชว์ full lifecycle ของ MIND ในรอบเดียว

## Scenario

ABC Corp / prod server down / Dashboard + payment API / user overloaded

## Copy-Paste Inputs

### Brain Dump
```text
ABC Corp ทวงงานค้าง 2 ตัวในแชต
prod ล่ม 9 โมงจาก CPU spike ยังไม่มี RCA
งานค้างคือ Dashboard mockup กับ payment API
ทีมถามสเปกปุ่ม และสไลด์บ่ายสองยังโล่ง
ผมหิว สมองตื้อ ไม่รู้ควรเริ่มจากอะไร
```

### Clarification
```text
prod restart แล้วกลับมาบางส่วน แต่ยังไม่ปิด incident
Dashboard เหลือ layout KPI/table
payment API ยังไม่ deploy ต้องเช็ก response กับ backend
ยังไม่ตอบลูกค้า เพราะกลัว commit เวลาเกินจริง
```

## Presenter Script

### 0:00 - 0:20 Open
- “ผมจะโชว์รอบเดียวให้เห็นทั้งวงจร: Brain Dump -> Clarify -> ONE_ACTION -> Evidence -> Rescue -> Reentry”
- “เคสนี้คือ ABC Corp งานค้างสองตัว มี incident ตอนเช้า และทีมกำลังกดเรื่องสเปกกับสไลด์พร้อมกัน”

### 0:20 - 0:50 Brain Dump
**Click**
- `สร้างห้องใหม่`
- วาง Brain Dump
- กด `ไปต่อ`

**พูด**
- “ผมเริ่มจากข้อความรก ๆ ที่รวมลูกค้า แชต incident และความล้าไว้ในห้องเดียว”
- “เป้าคือให้ MIND ย่อยออกมาเป็นก้าวแรกที่ชัด ไม่ใช่สรุปกว้าง ๆ”

**จุดที่ต้องชี้**
- Brain Dump field
- loading / clarification state

**คาดหวังบนหน้าจอ**
- clarification อาจขึ้นหนึ่งครั้ง
- ไม่ควรเด้งกลับไปถามซ้ำ

### 0:50 - 1:20 Clarify
**Click**
- ถ้า clarification ขึ้นมา ให้วางคำตอบ
- กด `สรุปต่อเลย`

**พูด**
- “ผมตอบแค่ข้อมูลที่จำเป็น: incident status, Dashboard, payment API, และข้อจำกัดเรื่องยังไม่ตอบลูกค้า”
- “ถ้าขั้นนี้ผ่าน แปลว่า MIND รับบริบทพอจะไปต่อได้”

**จุดที่ต้องชี้**
- clarification box
- `สรุปต่อเลย`

**คาดหวังบนหน้าจอ**
- clarification ไม่วนซ้ำ
- ไปสู่ ONE_ACTION

### 1:20 - 2:10 ONE_ACTION
**พูด**
- “ตรงนี้คือหัวใจของ demo: one clear next action”
- “มันควรเล็ก พอเริ่มได้ และอิงกับ ABC Corp, server incident, Dashboard, หรือ payment API”

**จุดที่ต้องชี้**
- action title
- action rationale
- primary CTA

**คาดหวังบนหน้าจอ**
- action สั้น ชัด ไม่เป็น generic productivity advice

### 2:10 - 2:45 Evidence
**Click**
- เปิด `ดูที่มาและหลักฐานของก้าวนี้`

**พูด**
- “นี่คือหลักฐานว่าคำแนะนำมาจาก room context จริง”
- “ถ้า evidence ชี้กลับมาที่ข้อความในห้อง แปลว่าระบบไม่ได้แต่งเรื่องขึ้นมาเอง”

**จุดที่ต้องชี้**
- evidence chips
- source / excerpt panel

**คาดหวังบนหน้าจอ**
- evidence เปิดได้
- source อิง room text หรือ manual summary ที่ตรงกับบริบท

### 2:45 - 3:20 Rescue
**Click**
- กด `ฉันติดขัด / ช่วยวินิจฉัยจุดที่บล็อกอยู่`

**พูด**
- “ถ้าผมติด ผมอยากให้ Rescue บอกว่าติดเพราะอะไรจริง ๆ”
- “ในเคสนี้มันควรเข้าใจคนทำงานที่โดนทั้งลูกค้า แชต incident และงานค้างพร้อมกัน แล้วให้ recovery ที่ใช้ต่อได้ทันที”

**จุดที่ต้องชี้**
- diagnosis text
- recovery steps
- suggested message ถ้ามี

**คาดหวังบนหน้าจอ**
- Rescue พูดถึง pressure / overload / uncertainty / server incident
- มี step หรือข้อความที่เอาไปใช้ต่อได้

### 3:20 - 4:00 Reentry
**Click**
- Refresh หน้า หรือ reopen ห้องเดิม
- กด `ต่อจากจุดนี้`

**พูด**
- “นี่คือ save point ของห้อง”
- “ผมกลับมาแล้ว ยังต่อจากจุดเดิมได้ ไม่รีเซ็ตกลับไปเริ่มใหม่”

**จุดที่ต้องชี้**
- reentry card / room header
- `ต่อจากจุดนี้`
- last-known-good / saved state

**คาดหวังบนหน้าจอ**
- room state เดิมยังอยู่
- ไม่กลับไป DUMP_ENTRY

## Fallback Talking Points

- “ถ้าคำพูดของ AI เปลี่ยนเล็กน้อย ให้ดูโครง: clarification ครั้งเดียว, ONE_ACTION, Evidence, Rescue, Reentry”
- “ถ้า wording ต่างจากสคริปต์นิดหน่อย แต่ยังยึด ABC Corp / server / Dashboard / payment API ถือว่าผ่าน”
- “ถ้า Rescue เขียนคนละประโยค แต่ยังระบุ blockage จริงและ recovery ใช้ได้ ก็ใช้ได้”

## Do-Not-Claim

- อย่าบอกว่า incident ถูกแก้จบแล้ว
- อย่าบอกว่า RCA เสร็จแล้ว
- อย่าบอกว่า customer reply สุดท้ายเป็นคำตอบที่ยืนยันแล้ว
- อย่าบอกว่า evidence เป็น full document parse ถ้ามาจาก room context
- อย่าบอกว่า Rescue เป็นคำตอบเดียวที่ถูกต้อง

## Closing Line

- “MIND เปลี่ยน brain dump ที่รกให้เหลือ next action ที่อ้างหลักฐานได้ และถ้าติดก็ยังให้ recovery ที่ใช้ต่อได้โดยไม่รีเซ็ตงาน”

## Demo Risks

- Rescue wording อาจเปลี่ยนเล็กน้อยตามรอบ AI
- Reentry ควรโชว์บนห้องที่มี save point จริง
- browser extension หรือ translation tool อาจทำ noise ที่ไม่เกี่ยวกับ product
- อย่าอ่าน Brain Dump ยาวกว่านี้ เพราะช่อง input จะแคบและมองไม่ดี

## 🎙️ เวอร์ชัน "พูดสด 2 นาที" (2-Minute Live Script)

บทพูดสดที่กระชับ เน้นจังหวะที่เร็วและเฉียบคม โดยมีเป้าหมายคือแสดง Lifecycle ทั้งหมดอย่างรวดเร็ว

### [0:00 - 0:20] นำเข้าสู่สถานการณ์และปัญหา
* **[สิ่งที่ต้องทำบนจอ]**: เปิดหน้าแรกของ MIND ชี้เมาส์ไปที่ปุ่มสำหรับเริ่มต้นสร้างห้อง
* **[บทพูด]**: "สวัสดีครับ วันนี้ผมจะพาทุกคนมาดู Lifecycle ทั้งหมดของ MIND ภายใน 2 นาที เพื่อชี้ให้เห็นว่าเราเปลี่ยนความสับสนในสมองให้เป็นก้าวแรกที่ลงมือทำได้จริงได้อย่างไร เคสตัวอย่างในวันนี้คือ **ABC Corp** ที่ทวงงานค้างสองตัวเข้ามาในขณะที่ระบบโปรดักชันล่มเมื่อเช้า แถมทีมยังถามหาสเปก และมีพรีเซนต์ตอนบ่ายที่ยังไม่ได้ทำจนสมองตื้อไปหมดครับ"

### [0:20 - 0:50] การกรอกข้อมูลและการทำ Clarification
* **[สิ่งที่ต้องทำบนจอ]**: คลิก `สร้างห้องใหม่` -> วาง Brain Dump ลงไป -> กด `ไปต่อ` -> เมื่อ Clarification Box เด้งขึ้นมา ให้วางข้อความ Clarification ทันที -> กด `สรุปต่อเลย`
* **[บทพูด]**: "ผมนำข้อความบ่นดิบ ๆ หรือ Brain Dump ที่รกมาก ๆ วางลงในห้องทำงานใหม่ของ MIND แล้วกด 'ไปต่อ' ครับ สังเกตว่าระบบจะไม่ใช่แค่สรุปแบบกว้าง ๆ แต่จะวิเคราะห์และเด้งกล่องถามเพื่อชี้เป้าหาข้อมูลสำคัญที่เราอาจลืมบอกทันที ผมตอบบริบทเพิ่มไปว่าเซิร์ฟเวอร์เพิ่งรีสตาร์ทกลับมาบางส่วน และคีย์เวิร์ดของงานที่เหลืออยู่ จากนั้นกด 'สรุปต่อเลย' ครับ"

### [0:50 - 1:20] การแสดง ONE_ACTION และตรวจสอบหลักฐาน
* **[สิ่งที่ต้องทำบนจอ]**: รอผลลัพธ์ ONE_ACTION โหลดเสร็จ ชี้ไปที่หัวข้อ Action และ Rationale -> จากนั้นคลิกปุ่ม `ดูที่มาและหลักฐานของก้าวนี้` เพื่อเปิดแถบด้านข้าง
* **[บทพูด]**: "และนี่คือ ONE_ACTION หรือก้าวแรกที่ชัดเจนที่สุดครับ MIND จะเลือกงานที่เล็กและมีอิมแพ็คสูงที่สุดให้เราทำก่อนโดยไม่ปล่อยให้เราจมกับกองงาน และความสำคัญคือเมื่อคลิก 'ดูที่มาและหลักฐานของก้าวนี้' แถบด้านข้างจะโชว์หลักฐานเชื่อมโยงกลับไปที่ประโยคต้นทางในห้องของเราจริงๆ เพื่อพิสูจน์ว่านี่ไม่ใช่คำแนะนำที่นั่งเทียนเขียนขึ้นมาลอยๆ ครับ"

### [1:20 - 1:45] ฟังก์ชันการกู้ภัย (Rescue) เมื่อเจอปัญหา
* **[สิ่งที่ต้องทำบนจอ]**: ปิดแถบหลักฐาน -> คลิกปุ่ม `ฉันติดขัด / ช่วยวินิจฉัยจุดที่บล็อกอยู่`
* **[บทพูด]**: "แต่ในความเป็นจริง เรามักจะมีอุปสรรคหรือความกังวลจนเริ่มทำไม่ได้ เมื่อคลิกปุ่ม 'ช่วยวินิจฉัยจุดที่บล็อกอยู่' ระบบจะทำหน้าที่เป็นโค้ชวิเคราะห์สภาวะจิตใจและข้อติดขัดของเรา พร้อมออกแบบ Recovery Steps และคำพูดดราฟต์สั้นๆ ที่ดึงเอาประเด็นเซิร์ฟเวอร์ incident มาใช้เพื่อให้เราเอาไปสื่อสารต่อได้ทันทีครับ"

### [1:45 - 2:00] การเก็บความจำและการกลับมาทำต่อ (Reentry & Closing)
* **[สิ่งที่ต้องทำบนจอ]**: กด Refresh เบราว์เซอร์ หรือย้อนกลับไปหน้าแรก -> คลิกเข้าห้องเดิม -> โชว์ปุ่ม `ต่อจากจุดนี้`
* **[บทพูด]**: "สุดท้าย หากเราปิดหน้าจอไปเพื่อเคลียร์งานอื่น แล้วกลับเข้ามาใหม่ MIND จะจดจำ Save Point ของงานเดิมไว้ทั้งหมด เมื่อคลิก 'ต่อจากจุดนี้' เราจะทำงานต่อจากจุดเดิมได้ทันทีโดยไม่ถูกล้างค่าให้เสียเวลาครับ นี่คือ MIND เครื่องมือเปลี่ยนความยุ่งเหยิงให้กลายเป็นก้าวแรกที่มีทิศทางและมีหลักฐานอ้างอิงเสมอครับ ขอบคุณครับ"

## 📖 เวอร์ชัน "อ่านตามได้เลย 5 นาที" (5-Minute Detailed Script)

บทพูดเวอร์ชันละเอียดแบบคำต่อคำ เหมาะสำหรับผู้เริ่มนำเสนอเพื่อความแม่นยำสูงสุด แบ่งเป็นช่วงเวลาทีละนาทีอย่างเป็นระบบ

### [นาทีที่ 1] บทนำและนิยามปัญหา (0:00 - 1:00)
* **[สิ่งที่ต้องทำบนจอ]**:
  1. แชร์หน้าจอที่หน้า Home ของแอปพลิเคชัน MIND
  2. เลื่อนเมาส์ชี้ไปรอบๆ แดชบอร์ดห้องทำงานเพื่ออธิบายความสะอาดของอินเตอร์เฟส
* **[คำพูดสดคำต่อคำ]**:
  "สวัสดีผู้มีเกียรติและทีมงานทุกคนครับ วันนี้ผมมีความยินดีอย่างยิ่งที่จะพามาสัมผัสประสบการณ์จริงของ MIND ซึ่งเป็นผู้ช่วยอัจฉริยะที่ไม่ได้มาเพื่อสรุปข้อความธรรมดา แต่มาเพื่อแก้ปัญหาระดับสมองตื้อ หรือสภาวะ Cognitive Overload ของคนทำงานในยุคปัจจุบันครับ
  ลองจินตนาการถึงเช้าวันจันทร์ที่เซิร์ฟเวอร์ล่ม ลูกค้าทวงงาน ทีมงานถามหาสเปกปุ่ม และยังมีงานพรีเซนต์ที่รออยู่ ทุกอย่างรุมเร้าจนคุณไม่รู้ว่าควรหยิบอะไรขึ้นมาทำเป็นชิ้นแรก สุดท้ายคุณจะไม่ได้ทำอะไรเลยเพราะสมองปิดรับรู้
  ในวันนี้ผมจะสาธิต Lifecycle ทั้งหมดของ MIND เริ่มตั้งแต่การเทขยะในสมองออกไปจนถึงขั้นตอนที่เราได้ก้าวแรกที่มั่นใจและมีหลักฐานอ้างอิงชัดเจนครับ"
* **[จุดสังเกตเพื่อชี้ให้ผู้ฟังดู]**:
  - แถบนำทางด้านข้างที่เรียบง่าย
  - ปุ่ม `สร้างห้องใหม่` ที่เด่นชัดซึ่งเป็นจุดเริ่มต้นของเรื่องราวทั้งหมด
* **[เหตุผลเบื้องหลังของฟีเจอร์นี้]**:
  - การปล่อยให้ผู้ใช้เห็นหน้าจอที่คลีนที่สุดจะช่วยลด Cognitive Load ได้ทันทีตั้งแต่ก้าวแรกที่เปิดแอปพลิเคชัน

### [นาทีที่ 2] ถ่ายเทขยะในสมองและกรอกข้อมูลเพิ่ม (1:00 - 2:00)
* **[สิ่งที่ต้องทำบนจอ]**:
  1. คลิกปุ่ม `สร้างห้องใหม่`
  2. ก๊อปปี้ข้อความจากส่วน `Brain Dump` วางลงในอินพุตฟิลด์
  3. กดปุ่ม `ไปต่อ`
  4. รอสักครู่จน Clarification Box ปรากฏขึ้น จากนั้นวางข้อความตอบคำถามลงไปแล้วคลิก `สรุปต่อเลย`
* **[คำพูดสดคำต่อคำ]**:
  "ผมจะเริ่มสร้างห้องทำงานขึ้นมาหนึ่งห้องเปรียบเสมือนพื้นที่คิดส่วนตัว จากนั้นผมหยิบเอาข้อความบ่นดิบๆ หรือ Brain Dump ที่ไม่มีระเบียบ มีทั้งเรื่องงานเซิร์ฟเวอร์ล่ม งานค้าง Dashboard และความรู้สึกท้อแท้ วางลงไปตรงๆ แล้วกด 'ไปต่อ' ครับ
  ทุกคนจะสังเกตเห็นว่า MIND ไม่ได้เงียบหายไปประมวลผลระบบหลังบ้านเฉยๆ หรือให้คำตอบแบบเหมาเข่ง แต่ระบบจะทักเรากลับมาด้วยคำถามสั้นๆ หรือ Clarification ที่ตรงจุด เช่น ถามถึงเรื่องสถานะเซิร์ฟเวอร์ หรือสถานะปุ่มที่ทีมค้างไว้ ผมจะวางคำตอบสั้นๆ ลงไปเพื่อเติมบริบทให้ระบบ จากนั้นกด 'สรุปต่อเลย' ครับ"
* **[จุดสังเกตเพื่อชี้ให้ผู้ฟังดู]**:
  - สังเกตตัวชี้วัดหรือ Loading Indicator ที่เคลื่อนไหวอย่างสมูท
  - ความกระชับของคำถามใน Clarification Box ที่ไม่ยาวจนน่าเบื่อ
* **[เหตุผลเบื้องหลังของฟีเจอร์นี้]**:
  - Clarification เป็นกระบวนการบีบอัดข้อมูลส่วนขาด เพื่อไม่ให้ผู้ใช้ต้องเดาเอาเองว่า AI ต้องการอะไร ทำให้คำตอบสุดท้ายมีคุณภาพและสอดคล้องกับสถานการณ์จริงมากที่สุด

### [นาทีที่ 3] วิเคราะห์ ONE_ACTION และขุดหาหลักฐาน (2:00 - 3:00)
* **[สิ่งที่ต้องทำบนจอ]**:
  1. ชี้เมาส์ไปที่หัวข้อ ONE_ACTION ขนาดใหญ่ที่แสดงขึ้นมากลางหน้าจอ
  2. ชี้ไปที่ข้อความอธิบายเหตุผล (Rationale) ด้านล่าง
  3. คลิกปุ่ม `ดูที่มาและหลักฐานของก้าวนี้` เพื่อเปิดแผงหลักฐาน (Evidence Side Panel)
* **[คำพูดสดคำต่อคำ]**:
  "และนี่คือผลลัพธ์ที่เป็นหัวใจสำคัญครับ MIND มอบสิ่งที่เราเรียกว่า ONE_ACTION หรือ 'ก้าวถัดไปเพียงก้าวเดียว' ที่ชัดเจนที่สุด ในที่นี้ระบบแนะนำให้เราเริ่มจากงานที่ควบคุมได้ง่ายและด่วนที่สุดก่อน นั่นคือการเคลียร์สถานะ Dashboard หรือการตอบลูกค้าแบบสั้นๆ เพื่อลดแรงกดดัน
  แต่ความพิเศษที่ทำให้ MIND ต่างจาก AI ทั่วไปคือการกดปุ่ม 'ดูที่มาและหลักฐานของก้าวนี้' ครับ เมื่อผมคลิกเข้าไป จะปรากฏแผง Evidence ด้านข้างที่สกัดท่อนข้อความดั้งเดิมจากห้องทำงานมาให้ดูเลยว่า คำแนะนำนี้เชื่อมโยงกับปัญหาเซิร์ฟเวอร์ล่มและ Dashboard mockup ในแชตอย่างไร ทำให้ผู้ใช้มั่นใจได้ทันทีว่าระบบไม่ได้คิดคำตอบขึ้นมาเองลอยๆ ครับ"
* **[จุดสังเกตเพื่อชี้ให้ผู้ฟังดู]**:
  - แผงด้านข้างที่เปิดขึ้นมาอย่างนุ่มนวล
  - การใช้ Evidence Chips หรือไฮไลต์คำสำคัญที่ดึงมาจากต้นฉบับจริง
* **[เหตุผลเบื้องหลังของฟีเจอร์นี้]**:
  - การให้ข้อมูลที่มีการอ้างอิงกลับ (Traceability) เป็นการสร้าง Trust หรือความน่าเชื่อถือ ซึ่งสำคัญมากสำหรับผู้ใช้ที่กำลังเผชิญหน้ากับวิกฤตการทำงาน

### [นาทีที่ 4] การใช้ปุ่มกู้ภัย Rescue และการจัดการทางอารมณ์ (3:00 - 4:00)
* **[สิ่งที่ต้องทำบนจอ]**:
  1. ปิดแผง Evidence Panel
  2. คลิกปุ่ม `ฉันติดขัด / ช่วยวินิจฉัยจุดที่บล็อกอยู่` ด้านล่างของการ์ด ONE_ACTION
  3. เลื่อนดูข้อความการวินิจฉัย (Diagnosis) และแผนการกู้คืน (Recovery Steps) ที่ระบบแนะนำ
* **[คำพูดสดคำต่อคำ]**:
  "แน่นอนครับว่าในชีวิตจริง แม้คำแนะนำจะดีแค่ไหน แต่ถ้าเรายังมีอาการตื้อหรือรู้สึกมีแรงต้านจิตใจอยู่ เราก็อาจจะยังไม่เริ่มทำ ในจุดนี้ MIND จึงมีปุ่มพิเศษที่ชื่อว่า 'ช่วยวินิจฉัยจุดที่บล็อกอยู่' หรือฟังก์ชัน Rescue ครับ
  เมื่อเราคลิกเข้าไป ระบบจะเปลี่ยนโหมดจากการวิเคราะห์ข้อมูลดิบ มาทำความเข้าใจภาวะอารมณ์และแรงกดดันของผู้ใช้ทันที ในตัวอย่างนี้ ระบบวินิจฉัยได้ชัดเจนว่าผู้ใช้กำลังวิตกกังวลเรื่องการตอบคำถามลูกค้าและการประสานงานที่รวดเร็วเกินไป จึงเสนอ Recovery Steps ที่แบ่งเป็นขั้นเล็กๆ เช่น ร่างข้อความที่จะส่งบอกสถานะกับ ABC Corp ให้ทันทีโดยที่เราไม่ต้องคิดประโยคเองเลยครับ"
* **[จุดสังเกตเพื่อชี้ให้ผู้ฟังดู]**:
  - น้ำเสียงของข้อความใน Rescue ที่มีความเข้าใจ (Empathetic Tone) และเน้นปฏิบัติจริง
  - กล่องคำแนะนำที่มีข้อความสำเร็จรูปพร้อมให้เราคัดลอกไปใช้งานได้เลย
* **[เหตุผลเบื้องหลังของฟีเจอร์นี้]**:
  - Rescue ไม่ได้ช่วยแค่เรื่องงาน แต่ช่วยเรื่องการปลดล็อกอารมณ์ความเครียดของผู้ใช้ (Emotional Rescue) เพื่อให้ก้าวข้ามสภาวะชะงักงันหรือการผัดวันประกันพรุ่งได้

### [นาทีที่ 5] การคงอยู่ของบริบทและการกลับเข้ามาใหม่ (4:00 - 5:00)
* **[สิ่งที่ต้องทำบนจอ]**:
  1. กดปุ่มรีเฟรชหน้าเบราว์เซอร์ (F5 / CMD+R) เพื่อแกล้งทำให้ระบบหลุด หรือย้อนกลับหน้าแรกแล้วคลิกเลือกห้อง ABC Corp เดิมกลับขึ้นมา
  2. เลื่อนลงมาเพื่อโชว์ปุ่ม `ต่อจากจุดนี้`
  3. กล่าวคำสรุปปิดท้ายอย่างประทับใจ
* **[คำพูดสดคำต่อคำ]**:
  "ฟีเจอร์สุดท้ายที่เป็นการยืนยันเรื่องความอุ่นใจในการใช้งานคือ **Reentry หรือการกลับเข้าสู่บริบทเดิม** ครับ ถ้าวันนั้นไฟดับ เบราว์เซอร์ค้าง หรือผมจำต้องปิดแอปพลิเคชันไปพักผ่อน เมื่อผมเปิด MIND กลับมาและเปิดห้อง ABC Corp นี้ขึ้นมาอีกครั้ง ทุกคนจะเห็นหน้าต่างบันทึกสถานะหรือ Save Point ล่าสุดที่พร้อมปุ่ม 'ต่อจากจุดนี้'
  เมื่อคลิกแล้ว หน้าจอและข้อมูลการทำงานที่ค้างไว้จะกลับคืนมาแบบ 100% โดยที่ประวัติและความทรงจำของงานไม่หายไปไหนเลยครับ
  สรุปสั้น ๆ ครับ MIND คือแอปพลิเคชันที่เข้ามาเปลี่ยนกระดาษทดที่ยุ่งเหยิงในหัว ให้กลายเป็นก้าวแรกที่ลงมือทำได้จริง มีหลักฐานที่มาที่ชัดเจน และมีระบบโอบอุ้มสภาพจิตใจในยามที่เราติดขัด เพื่อให้คนทำงานทุกคนสามารถก้าวไปข้างหน้าได้อย่างมั่นคงครับ ขอบคุณมากครับ"
* **[จุดสังเกตเพื่อชี้ให้ผู้ฟังดู]**:
  - สภาพแวดล้อมของแอปพลิเคชันที่ฟื้นคืนสถานะเดิมอย่างสมบูรณ์แบบโดยไม่ต้องโหลดบริบทใหม่ตั้งแต่ต้น
  - ปุ่ม `ต่อจากจุดนี้` ที่เปลี่ยนสีหรือไฮไลต์เพื่อกระตุ้นให้คลิกทำต่อ
* **[เหตุผลเบื้องหลังของฟีเจอร์นี้]**:
  - การรักษา context หรือความต่อเนื่อง ( continuity) เป็นปัจจัยสำคัญในการลดพลังงานสมองในการสลับงาน (Context Switching Cost) เพื่อให้ผู้ใช้กลับมารันงานต่อได้อย่างลื่นไหลและไร้รอยต่อที่สุด

## 🎯 เคสไฮไลท์สำหรับนำเสนอ Demo (Highlight Demo Cases)

เพื่อให้เห็นความสามารถและจุดเด่นของระบบได้อย่างชัดเจนที่สุด การเลือกโชว์เคสที่ **มี Clarification** และ **ไม่มี Clarification** จะช่วยสาธิตความยืดหยุ่นและการทำงานเชิงลึกของ MIND ได้ดีที่สุด ดังนี้ครับ:

### 1. ทำไมบางเคสถึงต้องมี หรือไม่มี Clarification?

* **เคสที่มี Clarification (มีปฏิสัมพันธ์เพื่อเติมเต็มบริบท)**:
  ระบบจะเลือกเข้าสู่โหมดนี้เมื่อตรวจพบว่าข้อความ Brain Dump ต้นทาง **มีความคลุมเครือสูง ข้อมูลไม่ปะติดปะต่อ หรือเต็มไปด้วยความขัดแย้งเชิงเวลาและทรัพยากร** AI จะหยุดเพื่อขอ Clarification ก่อน เพื่อช่วยกระตุ้นความทรงจำและบีบอัดข้อมูลส่วนที่ขาดหาย ทำให้คำแนะนำ ONE_ACTION มีทิศทางและไม่ฟุ้งซ่าน
* **เคสที่ไม่มี Clarification (ข้ามตรงสู่ความก้าวหน้าอย่างรวดเร็ว)**:
  ระบบจะเลือกข้ามขั้นตอนการถามคำถามเมื่อตรวจพบว่า Brain Dump ต้นทาง **มีเป้าหมายที่เฉพาะเจาะจง มีรายละเอียดของงาน ข้อจำกัดด้านเวลา หรือตัวเลขอ้างอิงที่ครบถ้วนและชัดเจนอยู่แล้ว** AI จะคำนวณและเลือก ONE_ACTION ออกมาได้ทันทีตั้งแต่คลิกแรก เพื่อมอบความก้าวหน้าที่รวดเร็วที่สุดให้กับคนทำงาน

---

### 2. กลุ่มเคสไฮไลท์ที่แนะนำสำหรับการ Demo

#### 🏆 เคสที่ 1: [มี Clarification] วิกฤตการณ์หลายมิติสะสม (Multi-dimensional Crisis Flow)
* **จุดเด่นที่โชว์**: แสดงความสามารถในการ "จัดระเบียบ" (Disentanglement) และการสกัดเอาแกนอารมณ์/ความตึงเครียดของเหตุการณ์ที่ประดังประเดเข้ามาพร้อมกัน
* **ตัวอย่าง Input (Brain Dump)**:
  ```text
  ABC Corp ทวงงานค้าง 2 ตัวในแชต
  โปรดักชันล่มตั้งแต่เช้า ยังไม่ปิด incident
  ทีมถามสเปกปุ่มบ่ายนี้
  สไลด์ลูกค้าบ่ายสองยังโล่ง
  ผมเริ่มตื้อไปหมดแล้ว หิวข้าวด้วย
  ```
* **คำตอบตัวอย่างสำหรับ Clarification**:
  ```text
  incident เริ่มจาก CPU spike บน app server
  งานค้างคือ Dashboard กับ payment API
  ยังไม่ตอบลูกค้า เพราะกลัว commit เกินข้อมูล
  ```
* **จุดไฮไลท์สำคัญตอนเดโม่**:
  1. **โชว์ Clarification Box**: เสนอแนะคำถามเฉพาะเจาะจง 3 ข้อสั้น ๆ เพื่อช่วยจัดระเบียบ
  2. **โชว์ Evidence**: ชี้ให้เห็นว่า ONE_ACTION ดึงมาจากประเด็นเซิร์ฟเวอร์และข้อความทวงงานของ ABC Corp
  3. **โชว์ Rescue**: แสดงความเข้าใจในความเครียดจากเหตุการณ์ล่ม และร่างข้อความสำหรับส่งคุยลดแรงกดดันกับลูกค้า

#### ⚡ เคสที่ 2: [ไม่มี Clarification] แผนงานเฉพาะกิจเน้นความก้าวหน้า (Focused Slide Setup)
* **จุดเด่นที่โชว์**: โชว์ความเร็วและการสกัด "ก้าวแรกที่ทรงพลัง" จากบริบทเนื้อความและตัวเลขดิบที่ครบอยู่แล้ว โดยไม่มีการถามคำถามให้เสียจังหวะ (Zero-friction path)
* **ตัวอย่าง Input (Brain Dump)**:
  ```text
  พรีเซนต์ผู้บริหาร 16:00 มีตัวเลขคร่าว ๆ คือ downtime ลด 20% ticket ซ้ำลด 15% หัวหน้าอยากเน้นเรื่อง impact และความรวดเร็ว ไม่มีไฟล์แนบ มีแต่ข้อความนี้ครับ
  ```
* **จุดไฮไลท์สำคัญตอนเดโม่**:
  1. **ข้าม Clarification ทันที**: กด `ไปต่อ` แล้ววิ่งทะลุเข้าสู่ ONE_ACTION ภายในพริบตาเดียว
  2. **โชว์ Evidence Honesty**: เปิดหลักฐานขึ้นมาจะเห็นชัดเจนว่าระบบระบุที่มาจากข้อความเปล่า ๆ และ **ไม่ประดิษฐ์หรือมโนไฟล์แนบขึ้นมาเอง** (No invented files) ซึ่งแสดงถึงความสัตย์ซื่อของ AI

#### 🛡️ เคสที่ 3: [มี Clarification] ทางตันด้านการตัดสินใจและเทคนิค (Technical & Stakeholder Blockage)
* **จุดเด่นที่โชว์**: แสดงความสามารถในการแก้ปัญหาเชิงสภาวะจิตใจของคนทำงาน เมื่อผู้ใช้งานกลัวการเปิดใช้ Jira หรือไม่กล้าประสานงานเนื่องจากแรงกดดันสะสม
* **ตัวอย่าง Input (Brain Dump)**:
  ```text
  ผู้จัดการรอแผนลด bug วันนี้ มี alert payment webhook fail 3 ครั้ง QA รอคำตอบเรื่อง release เย็นนี้ ผมยังไม่กล้าเปิด Jira เลยครับ
  ```
* **คำตอบตัวอย่างสำหรับ Clarification**:
  ```text
  webhook fail เพราะ timeout จาก provider
  release ยังไม่ควรยืนยัน ต้องเช็ก bug critical ก่อน
  ```
* **จุดไฮไลท์สำคัญตอนเดโม่**:
  1. **โชว์ Rescue ที่ทรงพลังมาก**: ปุ่มกู้ภัย Rescue จะวิเคราะห์แรงต้านจิตใจที่ผู้ใช้บอกว่า "ไม่กล้าเปิด Jira" และให้ทางออกแบบ Practical Steps ที่ทำได้ทันทีโดยไม่ต้องยุ่งกับ Jira ก่อน ช่วยดึงเอาประเด็น payment fail มาดราฟต์ข้อความสื่อสารสากลลดความเครียดทันที

| :--- | :--- | :--- | :--- | :--- |
