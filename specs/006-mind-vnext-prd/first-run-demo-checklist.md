# MIND First-Run Demo Checklist

## Goal

Validate that a first-time user understands these two truths without explanation:

- `เริ่มจากพิมพ์งานได้เลย`
- `ไม่มีไฟล์ก็เริ่มได้`

## Demo Setup

- เปิดหน้าแรกของ MIND โดยปิด walkthrough ถ้าต้องการดู first-run แบบตรงไปตรงมา
- อย่าอธิบายล่วงหน้าว่าควรพิมพ์อะไรหรือควรแนบไฟล์ไหม
- ถ้าเจอ rescue fail ให้ปล่อยให้ผู้ใช้เห็นข้อความเองก่อน

## Tasks

### Task 1: Start with text only

พูดกับผู้ใช้:

> ลองใช้แอปนี้เพื่อเริ่มงานที่ค้างอยู่สักหนึ่งงาน

สิ่งที่ต้องสังเกต:

- ผู้ใช้เริ่มพิมพ์เลยไหม
- ผู้ใช้ลังเลหาไฟล์ก่อนหรือไม่

### Task 2: Decide whether files are required

ถามหลังผู้ใช้เห็นหน้าแรกหรือเริ่มพิมพ์แล้ว:

> ถ้าจะเริ่มตอนนี้ คุณคิดว่าต้องอัปโหลดไฟล์ก่อนหรือเปล่า

สิ่งที่ต้องสังเกต:

- ผู้ใช้ตอบว่าไฟล์ไม่จำเป็นไหม
- ผู้ใช้เข้าใจไหมว่าไฟล์เป็น optional context

### Task 3: Recover from rescue failure

พาผู้ใช้ไปถึงจุด rescue แล้วถ้ามี failure copy ให้ถาม:

> ตอนนี้คุณคิดว่างานหรือข้อความที่พิมพ์ไว้หายไหม

สิ่งที่ต้องสังเกต:

- ผู้ใช้รู้สึกว่าบริบทยังอยู่ครบไหม
- ผู้ใช้รู้ไหมว่าลองใหม่ทีหลังได้

## Pass / Fail Questions

1. ผู้ใช้เริ่มพิมพ์เลยไหม
2. ผู้ใช้เข้าใจไหมว่าไฟล์เป็น optional context
3. ตอน rescue fail ผู้ใช้คิดว่าข้อมูลหายหรือไม่

## Success Criteria

- ผู้ใช้อย่างน้อย 1 คนตอบหรือแสดงพฤติกรรมว่า “พิมพ์ก่อนก็ได้”
- ผู้ใช้ไม่ถามว่า “ต้องอัปโหลดไฟล์ก่อนหรือเปล่า” ก่อนเริ่ม
- ถ้า rescue fail ผู้ใช้ตอบว่า “งานยังอยู่” หรือเทียบเท่า

## Follow-Up Rule

ถ้าผู้ใช้ถามว่า `ต้องอัปโหลดไฟล์ก่อนหรือเปล่า` ให้ถือว่าเป็น UX/copy regression ทันที

- อย่าตีความว่าเป็นความผิดของผู้ใช้
- เก็บเป็นงาน follow-up รอบถัดไปพร้อม screenshot หรือคำพูดจริงที่ผู้ใช้ใช้
