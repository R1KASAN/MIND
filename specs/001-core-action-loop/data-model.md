Use [README.md](/Users/ark1/Public/MIND/README.md), [docs/demo-runbook.md](/Users/ark1/Public/MIND/docs/demo-runbook.md), and `npm run gate:phase5` for the active local workflow.

## Core Entities

### BrainDump
Represents the unstructured input provided by the user when they first enter the application.
- `id`: string (UUID)
- `content`: string (Raw text from the user)
- `createdAt`: Date

### Action
Represents the synthesized, actionable task generated by the AI from a BrainDump.
- `id`: string (UUID)
- `description`: string (The bite-sized string representing the action)
- `status`: enum (`pending`, `active`, `done`, `discarded`)
- `parentDumpId`: string (Reference to BrainDump id)
- `createdAt`: Date
- `completedAt`: Date | null

### AppSession
Represents the high-level flow state of the user to determine which UI mode to show and whether a "bounce-back" or "rescue" is needed upon app launch.
- `lastActiveDate`: Date (Used to determine if session dropped off)
- `currentMode`: enum (`brain_dump`, `start_now_preview`, `focus_mode`, `rescue_mode`, `bounce_back`)
- `activeActionId`: string | null (The action the user is currently focused on)

## AI Input/Output Contracts

**Input to AI API (Synthesize Action):**
```json
{
  "user_dump": "string (the BrainDump text)",
  "context": "string (e.g., 'user requested to simplify previous action XYZ')"
}
```

**Output from AI API (Structured Format):**
```json
{
  "next_action": "Buy milk from the store"
}
```

## State Transitions
1. `brain_dump` -> (AI Synthesizes) -> `start_now_preview`
2. `start_now_preview` -> (User clicks Start) -> `focus_mode`
3. `focus_mode` -> (User clicks Complete) -> `brain_dump` (or fetches next action internally)
4. `focus_mode` -> (User clicks Stuck) -> `rescue_mode`
5. `focus_mode` -> (Timeout / App closed, returns later) -> `bounce_back`
